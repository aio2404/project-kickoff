# Product discovery and first delivery

Read for project rules, scope and implementation handoff. Do not turn one previous project's domain, language, stack, privacy requirements or prototype constraints into universal defaults.

## Ask only consequential questions

Recover known answers before asking about the user, task, intended outcome, prototype versus durable implementation, authorized data, preferred interface, hosting, budget and autonomy. For UI work ask about useful visual references without copying a brand. Offer a recommendation and its tradeoff.

For beginners, one decisive question at a time is often appropriate. Do not re-confirm every known fact or let a tool's onboarding restart discovery. Do not choose static HTML only because setup disabled networking; choose technology for the intended outcome. Do not force a framework onto a tiny exploratory mockup either.

## Durable instructions

CLAUDE.md and AGENTS.md should contain essential obligations and verified project-specific details: purpose, useful references, known check commands, authorized data/actions, preservation rules and completion evidence. Avoid generic instruction catalogues. Preserve existing authority and reconcile disagreements before synchronizing files.

Use PRODUCT.md when a design tool requires it or it materially supports the project. Keep the journey, empty/error/ambiguous states, data and acceptance criteria explicit. Label simulated AI behavior; keyword matching can be wrong and does not evaluate a language model. An accessibility target is not a verified conformance claim.

For data residency requirements, distinguish interface language, company jurisdiction, storage, inference, backups, logs, subprocessors and connected services. Do not infer regulatory compliance from a hosting location. Development tools using cloud models are a separate data flow to review.

## Executable plan

Prefer a few coherent tasks producing a complete first journey. Tests should cover meaningful behavior and risk, not mirror every implementation detail. Request missing prerequisites when they become necessary, grouping related permissions.

Approval of a plan covers its implementation and corrections within scope, not just a single file. The coordinator delegates and verifies; the user decides material product changes and newly consequential operations. Make the model choice explicit rather than adopting an accidental default; compare alternatives on representative tasks when justified.

## Evidence and handoff

- Compare changes with the baseline and preserve existing work.
- Run relevant checks; another agent's success statement is not evidence.
- For UI, test actual interaction at mobile/desktop widths, keyboard navigation and failure states. Screenshots are not interaction tests; automated tests do not establish user comprehension.
- For an AI feature, maintain independent reference cases and distinguish retrieval, answer accuracy, authorization and actual action outcomes.
- Report working/simulated/unverified features and provide access to the result when possible. No implicit deployment.

If a checkpoint is useful, keep it concise: current goal and approved scope, confirmed decisions with sources, profile/interface/observed versions without secrets, authorizations, latest evidence, limits and next action. Recheck unstable facts at their sources. Do not accumulate transcripts, credentials or confidential records.
